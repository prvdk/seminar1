# Сценарий скринкаста по Postman-коллекции

## Цель видео

Показать, что для сервиса управления спутниковыми группировками КА сформирована Postman-коллекция на основе REST API проекта, запросы сгруппированы по смыслу, выполняются на локальном сервере и содержат автоматические проверки ответов.

## Что подготовить перед записью

1. Запустить сервис проекта на `http://localhost:8080`.
2. Открыть Postman.
3. Импортировать файл `postman/space-operation-center.postman_collection.json`.
4. Проверить переменные коллекции:
   - `baseUrl`: `http://localhost:8080`
   - `constellationName`: `Geo-1`
   - `satelliteName`: `Comm-1`
   - `entityId`: `1`

## Речь для скринкаста

Здравствуйте. В этом видео я показываю коллекцию Postman для тестирования сервиса управления спутниковыми группировками космических аппаратов.

Коллекция называется "API центра управления спутниковыми группировками". Она подготовлена для локального запуска сервиса на адресе `http://localhost:8080`. Базовый адрес вынесен в переменную `baseUrl`, поэтому при необходимости его можно быстро изменить без редактирования каждого запроса.

В коллекции есть несколько разделов. Первый раздел называется "Операции". Здесь находятся основные бизнес-сценарии сервиса: добавление спутников в группировку, активация группировки, выполнение миссии для всей группировки, выполнение миссии для одного спутника, получение сводки, получение статуса группировки и вывод спутника из эксплуатации.

Покажу первый запрос: "Добавить спутники в группировку". В теле запроса передается имя группировки и список спутников. В примере добавляются два спутника: спутник связи с типом `COMMUNICATION` и спутник съемки с типом `IMAGE`. У каждого спутника задается имя, уровень заряда батареи и специфичный параметр: пропускная способность для спутника связи или разрешение съемки для спутника наблюдения.

Отправляю запрос. Сервер возвращает созданную или найденную группировку со списком добавленных спутников. Во вкладке Tests видно, что для запроса добавлены проверки: статус ответа должен быть 200, имя группировки должно совпадать с переменной коллекции, а список спутников должен быть непустым.

Далее выполняю запрос "Активировать группировку". Этот запрос активирует все спутники в группировке, если у них достаточно заряда. Ответ успешный, тест проверяет статус 200.

Теперь запускаю запрос "Выполнить миссию группировки". В теле запроса указан `targetType` со значением `CONSTELLATION`, поэтому миссия выполняется для всех спутников выбранной группировки. После выполнения Postman показывает успешный статус, а автоматический тест подтверждает корректность ответа.

Следующий запрос — "Выполнить миссию одного спутника". Здесь `targetType` равен `SINGLE_SATELLITE`, дополнительно передается имя спутника из переменной `satelliteName`. Таким образом можно проверить выполнение миссии не для всей группировки, а для конкретного аппарата.

После этого открываю запрос "Получить сводку". Он возвращает текстовую сводку по спутниковым группировкам. Проверка убеждается, что ответ успешный и не пустой.

Запрос "Получить статус группировки" возвращает подробную информацию по выбранной группировке: имя, спутники, состояние и параметры. В тестах проверяется, что имя группировки совпадает с ожидаемым и что в ответе есть массив спутников.

Также в коллекции есть CRUD-разделы. Они нужны для прямого тестирования сущностей базы данных: группировок, спутников, энергосистем и состояний спутников. Эти запросы позволяют создать, получить, обновить и удалить записи напрямую через соответствующие REST-контроллеры.

В разделе "Документация" есть запросы к `OpenAPI JSON` и `Swagger UI`. Запрос `OpenAPI JSON` обращается к `/v3/api-docs` и проверяет, что в ответе действительно есть поля OpenAPI-спецификации: `openapi` и `paths`. Это подтверждает, что документация API генерируется приложением.

В конце можно запустить коллекцию через Runner. Postman последовательно выполнит запросы и покажет результат автоматических проверок. Зеленые статусы тестов означают, что сервис отвечает корректно по ожидаемым сценариям.

Таким образом, в решении есть готовая Postman-коллекция с русскими названиями, примерами тел запросов, переменными окружения и скриптами проверки корректности ответов.

## Рекомендуемый порядок демонстрации запросов

1. `Документация / OpenAPI JSON`
2. `Операции / Добавить спутники в группировку`
3. `Операции / Активировать группировку`
4. `Операции / Выполнить миссию группировки`
5. `Операции / Выполнить миссию одного спутника`
6. `Операции / Получить сводку`
7. `Операции / Получить статус группировки`

Запрос `Вывести спутник из эксплуатации` лучше показывать в конце, потому что после него спутник удаляется из группировки.

## Что показать во вкладке Tests

Показать, что у запросов есть JavaScript-проверки:

```javascript
pm.test("Статус ответа 200", function () {
  pm.response.to.have.status(200);
});
```

Пример проверки тела ответа:

```javascript
pm.test("Ответ содержит группировку и список спутников", function () {
  const json = pm.response.json();
  pm.expect(json.constellationName).to.eql(pm.collectionVariables.get("constellationName"));
  pm.expect(json.satellites).to.be.an("array");
});
```
